# 深色模式灯泡 · Dark Mode Lightbulb

一个 Chromium 内核浏览器扩展：**一个灯泡开关，一键在「深灰深色模式」和「浅色模式」之间切换**，
并且按系统时间自动切换 —— **19:00 之后自动深色，07:00 之后自动浅色**。

> 已针对本机的 **Open Browser**（`D:\APP\open_browser\...\open_browser.exe`，Chromium 119 内核，360 出品）做过适配与路径探测。

---

## 一、开关放在哪里？（关于"图中红框区域"）

浏览器**自带的工具栏是特权界面（`chrome://` 页面），任何扩展都无法把自己的 DOM 插进去**，
这是 Chromium 的硬性限制，不是实现取舍问题。所以本扩展用两条互补的路线，都落在你圈出的那片区域里：

| 方案 | 位置 | 稳定性 | 说明 |
| --- | --- | --- | --- |
| **① 原生工具栏图标**（主推） | 工具栏右侧、地址栏右边那一排，和拼图图标同排 | ★★★★★ | 走标准 `chrome.action` 接口，浏览器原生绘制，**不碰任何页面代码**，绝对不会被网页样式污染或误伤 |
| **② 浮动灯泡**（后备） | 页面窗口**右上角**，紧贴工具栏下方 | ★★★★ | 工具栏图标被这套浏览器隐藏时用；基于 Shadow DOM 完全隔离，支持自由调整距底部/右下角的距离，可随时在弹窗里关掉 |

两个开关**状态实时互通**：点任意一个，另一个会立刻跟着亮/灭。

**灯泡的两种样子**

| 状态 | 外观 |
| --- | --- |
| 浅色模式 | 熄灭的灰色灯泡，右下有一点小标记 |
| 深色模式 | 点亮的暖黄灯泡 + 光晕，工具栏图标还会带一个「夜」字角标 |

## 二、深色模式是怎么实现的？（为什么不是纯黑）

扩展内置两套引擎，弹窗里可切换，默认「自动」：

### 引擎 A：原生强制暗色（CDP）—— 推荐
扩展通过 DevTools 协议的 `Emulation.setAutoDarkModeOverride`（见
[Chromium 协议文档](https://chromium.journaldev.googlesource.com/chromium/src/+/refs/tags/132.0.6831.0/third_party/blink/public/devtools_protocol/browser_protocol.pdl)）
让浏览器**自己的渲染管线**去强制暗色：

- 用的是 Chromium 的官方暗色算法，**整站生效**，连滚动条、表单控件、内嵌框架都一起变暗；
- 算法本身就把白底映射成 `#121212`~`#1e1f22` 这一档**深灰**，不会出现"纯黑底 + 纯白字"的刺眼组合；
- 图片、视频保持原色，不会变成底片；
- 不注入任何 CSS，页面自身的样式和脚本基本不受影响，**几乎不会把网页搞坏**。

> 本机实测：这套浏览器的 `chrome.dll` 里确实带有 `Emulation.setAutoDarkModeOverride`
> 和 `WebContentsForceDark` 特性，所以这条路是通的。
> 若发现点了灯泡页面没变化，说明该特性没被打开 —— 用「启动浏览器并加载扩展.bat」启动一次
> （脚本已带 `--enable-features=WebContentsForceDark`），或到 `chrome://flags/#enable-force-dark`
> 把 Force Dark Mode 设为 Enabled。

### 引擎 B：CSS 兜底 —— 保底能用
扩展注入 `src/content/dark.css`，给页面根节点加 `filter: invert(1) hue-rotate(180deg)`，
把白底翻成深灰底；图片/视频/画布二次反相保持原色。**任何网页都能立刻变暗**，
代价是极少数站点的固定定位元素（吸顶导航、全屏弹层）可能位置偏移。

### 引擎怎么选

| 设置 | 行为 |
| --- | --- |
| **自动（默认）** | 优先用原生；某个标签页原生失败（例如该页开着 DevTools）就**只对该页**降级为 CSS |
| 原生强制暗色 | 只用引擎 A |
| CSS 兜底 | 只用引擎 B |

## 三、自动切换规则

- **07:00 起 → 浅色**
- **19:00 起 → 深色**
- 后台每 **1 分钟**巡检一次系统时间，跨过时间点后 1 分钟内自动切换，**所有已打开的标签页一起切**；
- 浏览器一启动、扩展刚装好、设置改动时都会立刻校正一次；
- **手动优先**：你随时点灯泡手动切换，自动模式会**承认你这次选择**，一直保持到你手动改动的
  那个主题"本来不该出现"的时间段结束 —— 也就是**下一个时间点（07:00 或 19:00）一到就交还自动模式**。
  弹窗状态栏会写明「你手动切到了深色，下一个时间点自动恢复」；
  （改自动开关或改时间点会立刻取消手动优先，重新按时间决定）
- 两个时间点都能在弹窗里改成任意 `HH:MM`（支持跨夜配置，比如「22:00 深色 / 06:00 浅色」）；
- 不想要自动切换，把「按时间自动切换」关掉即可，纯手动。

## 四、安装（Open Browser，两种方式）

### 方式一：扩展管理页（推荐，和你之前装的划词助手一样）

1. 双击 **`一键安装.bat`**（或右键 `一键安装.ps1` → 使用 PowerShell 运行）。
   脚本会自动：把扩展目录复制到剪贴板 → 打开 `chrome://extensions`。
2. 在扩展管理页右上角打开 **「开发者模式」**。
3. 点 **「加载已解压的扩展程序」**（有的版本叫「加载解压缩的扩展」）。
4. 在弹出的选择框里 **Ctrl+V** 粘贴路径 → 选择文件夹：
   ```
   C:\Users\MR\Documents\deepseek-harness\default-workspace\dark-mode-lightbulb
   ```
5. 工具栏出现灯泡图标。如果没看到，点地址栏右边的**拼图图标**，在列表里找到
   「深色模式灯泡」并点旁边的**固定/图钉**按钮。
6. 随便开一个网页，点一下灯泡试试。

> 本机已经用同样方式装过 `deepseek-sidekick`（记录在 Open Browser 的 `Preferences` 里，
> `extensions.ui.developer_mode = true`），所以这条路本机确定可用。

### 方式二：命令行直接加载（扩展管理页打不开时的备用方案）

1. 先**完全退出**浏览器（右上角 X）。
2. 双击 **`启动浏览器并加载扩展.bat`**。
   它会用 `--load-extension` + `--enable-features=WebContentsForceDark` 启动浏览器，
   并继续使用你原来的配置目录 `D:\APP\open_browser\Chrome\User Data`（登录状态、书签都在）。
   脚本默认会先强杀残留进程（`KILLFIRST=1`），不想强杀就把它改成 `0`。
3. 缺点：**每次都要用这个脚本启动**才会有这个扩展；日常还是建议用方式一。

### 想装到 Chrome / Edge？
步骤完全一样，把 `chrome://extensions` 换成 `edge://extensions` 即可（Edge），
扩展本身是标准 Manifest V3，通用。

## 五、使用说明

点灯泡图标打开弹窗：

- **大开关**：立刻切深色/浅色（手动切换会一直保持，直到下一个时间点自动恢复）；
- **按时间自动切换** + 两个时间框：改 07:00 / 19:00；
- **暗色渲染引擎**：自动 / 原生 / CSS；
- **页面右下角浮动灯泡**：显示开关 + 「距底部」滑块，用来避开某些网站的悬浮按钮；
- **立即重新应用**：手动重刷所有标签页；
- **诊断**：输出 JSON，包含 `chrome.debugger` 是否可用、原生 attach 是否成功、
  每个标签页当前用的哪套引擎 —— 出问题时先看这里。

## 六、常见问题

### 顶部那条"已开始调试此浏览器"黄条怎么去掉？

**为什么它会连带关掉深色**：原生引擎的暗色是挂在 CDP 调试连接上的
（`Emulation.setAutoDarkModeOverride`）。一旦你点「取消」或「×」断开连接，
Chromium 会**立即撤销这个覆盖**，页面就回到浅色 —— 这不是 bug，是 CDP 覆盖的生命周期。

这条黄条也是 **Chromium 对 `chrome.debugger` 的固有提示**：只要扩展用调试接口控制标签页，
浏览器就必须告知用户（安全设计）。**没有任何 API 或开关能隐藏它**（能隐藏的只有自动化测试用的
`--enable-automation` 那条"正受到自动测试软件控制"，和这条不是一回事）。

所以要"没有黄条 + 保持深色"，只能换一条不碰调试接口的路：

> **弹窗 → 暗色渲染引擎 → 选「CSS 兜底（无黄条）」**

切换后扩展会：

1. 撤销所有标签页上的原生暗色覆盖；
2. **断开全部调试连接**（`tools/test-worker.js` 有专门断言，确保不是"名义上切了、连接还挂着"）；
3. 之后只用内联 CSS 反相渲染，**黄条不再出现**；
4. 选 CSS 引擎时点「诊断」也不会再去试探性 attach，否则一点诊断黄条又冒出来；
5. 已经挂在页面上的那条黄条，点「取消」或刷新一次页面即可消失。

### CSS 引擎的固定定位问题，以及「兼容模式」

CSS 引擎靠给根元素加 `filter` 实现反相，而**给根元素加 filter 会让它成为 `position: fixed`
后代的包含块** —— 于是吸顶导航、底部工具条会变成"随文档滚走"。

从 v1.0.5 起，扩展内置了**兼容模式**（弹窗里可开关，默认开）：

- 注入一小段脚本，把 `body` 直属的 fixed 元素改成 `absolute`，并在滚动/缩放时
  用 `requestAnimationFrame` 同步位置，**视觉行为与 fixed 等价**；
- 改动前会**完整记录原始内联 `style`**，关闭兼容模式、切回浅色、或换回原生引擎时
  **逐字还原**，不留 `absolute` 残留；
- 扩展自己的浮动灯泡被显式排除在外，不受影响；
- 已知取舍：只认**内联样式**里的 `top`/`bottom`。如果某元素是靠在样式表里写 `bottom: 0`
  定位的，可能被当成顶部锚点（表现为贴在视口顶部，比"滚走"可用得多）。
  遇到这种情况告诉我域名，我可以把判断改成读计算样式。

> ⚠️ 诚实说明：兼容模式的逻辑我**无法在本地实测**（沙箱禁止启动浏览器子进程，
> `FATAL: platform_channel.cc`）。目前能保证的是：注入函数是自包含的（有断言防止引用后台变量
> 导致 ReferenceError）、apply/restore 的调用时机有断言覆盖、还原逻辑可逆。
> 真实网页上的表现请你实际逛几站验证，有问题把域名发我。

| 现象 | 原因与处理 |
| --- | --- |
| **右下角灯泡点了没反应** | 见下面「灯泡点不动」专节 —— v1.0.6 已修，但**必须刷新页面**才生效 |
| 想去掉"已开始调试此浏览器"黄条 | 弹窗里把引擎换成「CSS 兜底（无黄条）」，见上一节 |
| 点黄条的「取消」后深色没了 | 正常现象（见上）。要长期无黄条请换 CSS 引擎 |
| CSS 模式下某站顶栏/底栏跟着滚动跑 | 打开弹窗里的「兼容模式」；已开还错位就把域名发我 |
| 弹窗里引擎显示 CSS，但页面没变暗 | 该页可能是 `chrome://`、扩展页或空白页，浏览器不允许注入 |
| 点灯泡后页面没变暗 | 原生引擎没生效。打开弹窗把引擎切到「CSS 兜底」立刻见效；或按第二节启用 `WebContentsForceDark` |
| 工具栏没有灯泡图标 | 点拼图图标 → 固定；若拼图图标也没有，说明这套浏览器阉割了工具栏按钮，改用浮动灯泡（默认已开启） |
| 浮动灯泡挡住了网页按钮 | 弹窗里把「距底部」调大/调小，或直接关掉浮动灯泡 |

| 弹窗里「诊断」显示 attach 失败 | 该标签页开着 DevTools，或页面对扩展受限（`chrome://`、扩展商店）。换普通网页再看 |

| 想让 19:00 变得不一样 | 弹窗里直接改时间框，支持任意 `HH:MM` |
| 不确定浏览器里跑的是哪一版 | 弹窗最底下一行写着版本号；鼠标悬停工具栏灯泡，提示里也带 `v1.0.6` |

### 「灯泡点不动」是怎么修的（v1.0.6）

**根因**：内容脚本点灯泡时调用的 `chrome.runtime.sendMessage` 在**后台不可用**时会
**同步抛异常**（`Extension context invalidated`），而旧代码没有 try/catch，
异常直接冒泡出 click 监听器 —— 用户看到的就是"点了没反应"。

什么时候后台会不可用：Service Worker 休眠（MV3 空闲 30 秒就会被回收）、扩展刚在
`chrome://extensions` 里被点过「刷新」、或者已打开页面里跑的还是上一代内容脚本
（扩展被刷新后，页面里旧脚本的上下文立即失效，而页面不会自动重载）。

**修法**（三层）：

1. **不崩**：消息发送统一走 `sendToBackground()`，内部 try/catch，后台不可用也不抛异常；
2. **不谎报**：点击后乐观更新外观，1.2 秒后去 storage **核对后台是否真的改了**。
   没改成就**回滚外观**，提示气泡显示「切换未生效 · 请在扩展页刷新后重载本页」，
   而不是让按钮显示一个假状态；
3. **不静默**：后台一轮同步里某个标签页失败不再中断整轮（`syncAll` 逐个 try/catch），
   弹窗也会把"后台正在重启"和普通错误区分开提示。

> 这个 bug 是 `tools/test-content.js`（首个版本）抓出来的 —— 它真的把内容脚本加载进一个
> 极简 DOM 里跑，并模拟点击。这也是为什么我一直坚持"没在测试里跑过的代码不交给用户"。

### 怎么确认"我改的代码到底生效了没有"

排障时最容易白忙的就是"明明改了却没反应"。三个一眼可辨的信号：

1. **弹窗底部**：`深色模式灯泡 · v1.0.3`；
2. **悬停工具栏灯泡**：提示为 `深色模式：已关闭（点击转深色）· v1.0.3`；
3. **扩展页错误面板里的堆栈行号**：如果堆栈指向的行号和当前文件对不上，
   说明那是**历史遗留的错误记录**（旧的 Service Worker 报错不会自动消失），
   点右上角「全部清除」即可。

> 本次就是这个情况：磁盘上早已是单文件版本（第 19-21 行是 `DEFAULTS`），
> 而错误堆栈显示的是旧文件的头部注释，属于没清掉的旧记录。

### 已知踩坑记录：Service worker registration failed. Status code: 15

**现象**：扩展页报 `Service worker registration failed. Status code: 15`，
展开后是 `Failed to execute 'importScripts' on 'WorkerGlobalScope': The script at
'chrome-extension://<id>/...' failed to load.`；扩展表现为**图标在、点了完全没反应**，
定时切换也不执行。

**经过**（两次，值得记下来）：

| 版本 | 写法 | 结果 |
| --- | --- | --- |
| 1.0.0 | `importScripts('../lib/storage.js')` | 解析成 `<扩展根>/lib/storage.js` —— `../` 被吞掉、`src/` 也没带上，文件不存在 |
| 1.0.1 | `importScripts('src/lib/storage.js')` | URL 已经正确（`.../src/lib/storage.js`），**但依然 fetch 失败** |

也就是说：这个 Chromium 分支里 `importScripts` **整体不可靠**，无论路径怎么写都可能加载不到第
二个文件。

**1.0.2 的修法：后台彻底单文件化，不再加载任何外部脚本。**

- 设置定义、`themeForTime` 等时间逻辑全部内联进 `src/service-worker.js`；
- CSS 兜底引擎从 `chrome.scripting.insertCSS({files})` 改为**内联样式字符串**注入，同样不碰路径；
- 弹窗也不再 `<script src="../lib/storage.js">`，只加载 `popup.js`，并新增"后台单文件零依赖"
  与"弹窗只加载一个脚本"两条自检；
- `src/lib/storage.js` 保留为参考实现 + 单元测试目标，`tools/check.py` 会校验两份
  `DEFAULTS` 与 `themeForTime` 没有漂移，所以不会出现"改了一处忘了另一处"。

**你只需要**：到 `chrome://extensions` 对本扩展点一次「刷新」🔄，然后**刷新已打开的网页**
（内容脚本要重新注入）。若刷新无效，就「移除」→ 重新「加载已解压的扩展程序」。
版本号应显示 **1.0.2 以上**。

> ⚠️ **修好之后这条红字还可能挂着**：扩展管理页的错误面板记录的是历史事件，
> 已经修好的报错不会自动消失。判断方法看**堆栈行号**：
> 如果堆栈指向的行号和当前文件内容对不上（例如指向的是文件头部注释，
> 而当前文件那个位置已经是 `DEFAULTS` 定义），那就是旧记录 ——
> 点右上角「全部清除」，刷新扩展，然后再看有没有**新**的红字出现。
> 想快速确认浏览器里跑的是哪一版：弹窗最底部有版本号，悬停工具栏灯泡的提示里也有。

> 教训已经固化成测试：`tools/test-worker.js` 会在 Node 里用假的 `chrome.*` API
> **真正加载并执行** service-worker.js，再跑完整链路（安装 → 读状态 → 手动切换 →
> 两种引擎 → 改时间 → 闹钟巡检 → 手动优先）。这类"装进浏览器才发现"的问题，
> 现在在命令行就会红。

## 七、文件结构

```
dark-mode-lightbulb/
├─ manifest.json                     # MV3 清单
├─ src/
│  ├─ service-worker.js              # 后台：**单文件零依赖**，设置 + 时间逻辑 + 定时巡检 + 两套引擎
│  ├─ lib/storage.js                 # 可读版参考实现（时间逻辑单测跑的就是它；check.py 校验与后台不漂移）
│  ├─ content/
│  │  ├─ floating-bulb.js            # 浮动灯泡（Shadow DOM 隔离，零依赖）
```
